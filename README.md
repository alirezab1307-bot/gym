# باشگاه پلیت — نمونه سایت باشگاه ورزشی

سایت تک‌صفحه‌ای فارسی (راست‌به‌چپ) با انیمیشن هالتر، برنامه هفتگی کلاس‌ها، مربی‌ها، اشتراک‌ها، محاسبه‌گر BMI، اسلایدر نظرات، سؤال‌های رایج و فرم ثبت‌نام جلسه رایگان.

```
plate-gym/
├─ frontend/          ← سایت (این پوشه روی Netlify منتشر می‌شود)
│  ├─ index.html
│  ├─ admin.html      ← صفحه دیدن درخواست‌ها (با توکن مدیر)
│  ├─ 404.html, favicon.svg, robots.txt
│  └─ assets/  style.css · app.js · config.js
├─ backend/           ← API (این پوشه روی Railway اجرا می‌شود)
│  ├─ server.js       ← بدون هیچ پکیج خارجی
│  └─ package.json
├─ netlify.toml       ← تنظیمات Netlify
└─ .gitignore
```

## دو حالت اجرا

| | فرم کجا ذخیره می‌شود | نیاز به Railway |
|---|---|---|
| **حالت الف (پیشنهادی برای تست)** | Netlify Forms (پنل Netlify) | خیر |
| **حالت ب** | بک‌اند ما روی Railway | بله |

اول حالت الف را انجام دهید. ساده است و فقط یک سرویس دارد. بعد اگر خواستید حالت ب را هم تست کنید.

---

## قدم ۰: تست روی کامپیوتر خودتان (اختیاری)

نیاز: نصب Node.js نسخه ۱۸ به بالا.

1. ترمینال اول، برای بک‌اند:
   ```
   cd backend
   ADMIN_TOKEN=test123 node server.js
   ```
   (در ویندوز CMD: `set ADMIN_TOKEN=test123 && node server.js`)
2. ترمینال دوم، برای سایت:
   ```
   cd frontend
   python -m http.server 8080
   ```
3. در `frontend/assets/config.js` مقدار `API_URL` را `"http://localhost:3000"` بگذارید.
4. مرورگر: `http://localhost:8080`

---

## قدم ۱: آپلود در GitHub

1. در github.com وارد حسابتان شوید (اگر ندارید، رایگان بسازید).
2. بالا سمت راست روی **+** و بعد **New repository** بزنید.
3. اسم مخزن: `plate-gym` را بنویسید. گزینه **Private** یا **Public** هر کدام مشکلی ندارد. **Create repository** را بزنید.
4. در صفحه‌ی مخزن، لینک **uploading an existing file** را بزنید.
5. **مهم:** فایل زیپ را از حالت فشرده خارج کنید. بعد **محتویات** پوشه‌ی `plate-gym` را بکشید و رها کنید (پوشه‌های `frontend` و `backend` و فایل‌های `netlify.toml` و `README.md`). خود پوشه‌ی `plate-gym` را آپلود نکنید. فایل `netlify.toml` باید مستقیم در ریشه‌ی مخزن باشد.
6. پایین صفحه **Commit changes** را بزنید.

نکته: فایل `.gitignore` ممکن است با کشیدن و رها کردن آپلود نشود. لازم نیست.

---

## قدم ۲ (حالت الف): انتشار سایت روی Netlify

1. در netlify.com با حساب GitHub خودتان ثبت‌نام کنید.
2. **Add new project** و بعد **Import an existing project** را انتخاب کنید.
3. **GitHub** را بزنید و دسترسی بدهید. مخزن `plate-gym` را انتخاب کنید.
4. تنظیمات Build را دست نزنید. فایل `netlify.toml` پوشه‌ی انتشار را خودش مشخص می‌کند (`frontend`) و build ندارد.
5. **Deploy** را بزنید. بعد از حدود یک دقیقه آدرسی مثل `https://اسم-تصادفی.netlify.app` می‌گیرید.
6. آدرس را باز کنید. سایت باید کامل نمایش داده شود.

### تست فرم در حالت الف
1. فرم را با اطلاعات نمونه پر و ارسال کنید. پیام «درخواست شما ثبت شد» را باید ببینید.
2. در پنل Netlify، پروژه را باز کنید و بخش **Forms** را ببینید. فرمی به اسم `join` باید آنجا باشد و درخواست شما داخلش.
3. اگر فرم را نمی‌بینید: در تب Deploys یک بار دیپلوی دوباره بزنید و دوباره بخش Forms را نگاه کنید.

اگر فقط این حالت را می‌خواهید، همین‌جا تمام است.

---

## قدم ۳ (حالت ب): بک‌اند روی Railway

1. در railway.com با GitHub ثبت‌نام کنید.
2. **New Project** و بعد **Deploy from GitHub repo** را بزنید و مخزن `plate-gym` را انتخاب کنید.
3. سرویس ساخته می‌شود. روی آن کلیک کنید و به **Settings** بروید:
   - بخش **Source** (یا Root Directory): مقدار را `/backend` بگذارید. این مهم‌ترین قدم است؛ چون مخزن هم فرانت دارد و هم بک‌اند.
4. به تب **Variables** بروید و دو متغیر بسازید:
   - `ADMIN_TOKEN`: یک رمز طولانی و تصادفی (حداقل ۲۰ حرف). جایی یادداشتش کنید.
   - `ALLOWED_ORIGIN`: آدرس سایت Netlify شما، بدون `/` در انتها. مثلاً `https://plate-gym.netlify.app`
5. در **Settings** به بخش **Networking** بروید و **Generate Domain** را بزنید. آدرسی مثل `https://plate-gym-production.up.railway.app` می‌گیرید.
6. بعد از پایان دیپلوی، این آدرس را در مرورگر باز کنید و `/api/health` را به آخرش اضافه کنید. باید ببینید:
   `{"ok":true,"service":"plate-gym-api"}`

---

## قدم ۴: وصل کردن فرانت به بک‌اند

1. در GitHub فایل `frontend/assets/config.js` را باز کنید و آیکون مداد (Edit) را بزنید.
2. مقدار را عوض کنید:
   ```js
   window.APP_CONFIG = {
     API_URL: "https://plate-gym-production.up.railway.app"
   };
   ```
   (آدرس خودتان، بدون `/` در انتها)
3. **Commit changes** را بزنید. Netlify خودکار سایت را دوباره منتشر می‌کند.
4. سایت را باز کنید، فرم را پر کنید و ارسال کنید.
5. برای دیدن درخواست‌ها: `آدرس-سایت/admin.html` را باز کنید، `ADMIN_TOKEN` را وارد کنید و «نمایش درخواست‌ها» را بزنید.

---

## چیزهایی که باید عوض کنید (سایت نمونه است)

- اسم، شماره تلفن، آدرس و ساعت کار: در `index.html` (فوتر و بخش `application/ld+json` بالای فایل)
- قیمت‌ها و اشتراک‌ها: در `index.html`، بخش `plans`
- برنامه کلاس‌ها: در `assets/app.js`، آرایه‌ی `SCHEDULE`
- مربی‌ها و نظرها: در `index.html`
- رنگ‌ها: متغیرهای بالای `assets/style.css`
- عکس واقعی باشگاه: پوشه‌ی `frontend/images` بسازید و عکس‌ها را به فرمت WebP و کم‌حجم بگذارید

## عیب‌یابی

| مشکل | علت و راه‌حل |
|---|---|
| فرم پیام «ارسال انجام نشد» می‌دهد | اگر `API_URL` خالی است، سایت باید روی Netlify باشد (روی کامپیوتر خودتان Netlify Forms کار نمی‌کند). اگر پر است، آدرس Railway را چک کنید. |
| فرم پیام «اتصال برقرار نشد» می‌دهد | `ALLOWED_ORIGIN` روی Railway با آدرس دقیق سایت Netlify یکی نیست (`https://` و بدون `/` آخر). |
| `/api/health` باز نمی‌شود | `Root Directory` روی `/backend` نیست، یا دیپلوی هنوز تمام نشده. تب Deployments و Logs را ببینید. |
| صفحه‌ی مدیر «توکن نادرست است» می‌دهد | `ADMIN_TOKEN` را دوباره از Variables کپی کنید. |
| فونت‌ها عوض نمی‌شوند | فونت از Google Fonts می‌آید. اگر در دسترس نباشد، سایت با فونت پیش‌فرض سیستم نمایش داده می‌شود و کار می‌کند. |
| ۴۲۹ (تعداد درخواست زیاد) | هر IP در ساعت حداکثر ۵ ثبت‌نام می‌تواند بفرستد. برای تست چند بار پشت‌سرهم ارسال نکنید. |

---

## محدودیت‌های مهم این نمونه (تست، نه نسخه نهایی)

- **ذخیره‌ی داده روی Railway:** درخواست‌ها در یک فایل روی دیسک سرور ذخیره می‌شوند. اگر سرویس دوباره دیپلوی شود، احتمالاً این فایل پاک می‌شود (مگر اینکه Volume وصل کنید). برای کار واقعی باید به Postgres مهاجرت کرد. در حالت الف (Netlify Forms) این مشکل نیست.
- **اعتبار و سقف پلن رایگان:** سقف Netlify Forms و اعتبار ماهانه‌ی هر دو سرویس ممکن است عوض شود. در پنل Usage خود سرویس‌ها چک کنید.
- **امنیت:** آدرس `admin.html` قابل حدس است، ولی بدون `ADMIN_TOKEN` چیزی نشان نمی‌دهد. توکن را ساده انتخاب نکنید و با کسی به اشتراک نگذارید.
- **نام دکمه‌ها:** نام دکمه‌ها و منوها در Netlify، Railway و GitHub ممکن است کمی با متن بالا فرق داشته باشد. مفهوم مراحل عوض نمی‌شود.
